# План развития Vibe Coding Maestro

Цель — законченный продукт: человек запускает одну команду, проект разворачивается и дальше живёт без ручного ремонта. План опирается на два независимых ревью версии 0.3.0-beta.3: путь нового пользователя и устройство изнутри.

## Главный шов

Проверки Maestro сравнивают состав файлов проекта с составом той версии, которая их запускает. До 0.3.0-beta.4 проекты звали Maestro через `@latest`, а `upgrade` умел обновлять только с 0.2. Значит, любой выпуск, меняющий состав файлов, сразу покрасил бы проверки во всех проектах, и обновить их было бы нечем. Поэтому первым идёт фундамент обновлений.

## 0.3.0-beta.4 — фундамент

Состав файлов проекта не меняется, поэтому выпуск ничего не ломает.

- `upgrade` с любой опубликованной версии; прошлые версии и их файлы объявлены в пакете.
- Точная версия Maestro в каждом созданном проекте вместо `@latest`; `upgrade` переписывает её сам. Обёртка `vibe-maestro` зависит от точной версии.
- Вместо `manifest-canonical-mismatch` — понятное сообщение: «проект версии X, проверьте или обновите так».
- Экономный CI: отмена устаревших прогонов, один быстрый прогон на ветке, полная матрица на pull request и `main`, `npm run check` перед пушем.
- Понятные ошибки в `create`, `doctor` и `preflight` вместо stack trace и `ENOENT`.
- README и руководство — только через `npx`, без обещаний, которых код не выполняет.

## 0.3.0 — готовый продукт

Все изменения состава файлов — одним заходом, с миграцией в `upgrade` с 0.3.0-beta.3 и beta.4.

- Цикл «план утверждён → работа» описан и проверяется; `doctor` и `preflight` не противоречат друг другу по статусу плана.
- Личность проекта — по `project.id`, а не по имени папки; Unicode в путях приводится к NFC. Повторный `create` не переписывает отображаемое имя и даты.
- `doctor` не ругается на то, что велят сами протоколы; `wiki/index.md` принадлежит проекту; есть образцы передачи, ADR и записи хода работы.
- Правила честности — в `.claude/rules/` (файл Maestro), правила проекта — в своём файле рядом; `AGENTS.md` ссылается на те же правила.
- `.claude/settings.json` с запретами: не читать `.env`, не править файлы Maestro; push, publish и удаление — только с вопросом.
- Ревьюер только читает; есть помощник-разведчик для больших файлов.
- Навыки: пустые рекомендации убраны; в протоколе есть шаг выбора навыков — установленные, официальные каталоги, чужое только после «да» человека, в плане записано, что взято.
- Изменение плана после утверждения замечается.
- Прерванный `create` оставляет метку и говорит, что убрать.
- Сценарий нового пользователя проверяется автотестом; перед публикацией — независимое ревью.

## 0.4 — движок для длинных проектов

Начинается только после выпуска 0.3.0.

- Команда `vibe-maestro handoff`.
- Учёт закрытых порций плана.
- Проект под заказ вместе с брифом одной командой.
- Контроль размера `wiki/hot.md` и передач.
- Раздел о коннекторах (MCP).
- Меньше мелких протоколов.
- Проверка «замка» утверждения: гипотеза — команда, которую человек вводит сам в своём терминале.

## Не делаем

- Автоустановку навыков и коннекторов.
- ИИ внутри проверок: `doctor` и `preflight` остаются детерминированными.
- Два активных плана одновременно.
- Проверки на каждую правку файла.
- Английскую версию шаблонов сейчас.
