# Converter и миграция legacy-проектов

> **Статус 0.3 beta:** Converter отложен и не входит в Core. Обновление канонического проекта прошлой версии — отдельная команда `upgrade`, это не Converter.

Core Vibe Coding Maestro работает только с новым пустым каталогом или уже валидным canonical project текущей схемы. Core не преобразует непустой неканонический проект и не перезаписывает пользовательские файлы ради «подключения». Флага, который отменяет этот отказ, нет: прежний `--force` ничего не делал и удалён.

## Что доступно сейчас

- `vibe-maestro doctor --path <проект>` выполняет read-only проверку уже канонического проекта;
- `vibe-maestro upgrade --path <проект>` обновляет только доказуемо канонический проект известной прошлой версии Maestro; без `--apply` ничего не пишет;
- анализ чужого или legacy-проекта можно проводить только вручную и read-only;
- для эксперимента создавайте отдельный новый canonical project, не меняя исходный проект;
- backup и Git-ветка остаются ответственностью человека.

## Будущий отдельный Converter

Планируемый Converter будет отдельным модулем, а не режимом Core:

1. read-only анализирует исходный проект;
2. строит явный proposal и показывает конфликты;
3. создаёт новую staging-копию по канону Maestro;
4. не перезаписывает исходный проект;
5. проверяет полноту переноса и doctor;
6. требует человеческого подтверждения перед заменой рабочего процесса.

Converter приводит проект к канону Maestro. Канон и Core не адаптируются под legacy-структуру.

## Запрещённая подмена

В Core нет ни мигратора, ни Converter, ни обхода canonical boundary — ни флагом, ни повторным запуском. Подложный, foreign или неполный manifest не делает проект каноническим. Если Core отклоняет папку, остановитесь: не копируйте managed-файлы вручную поверх пациента и не используйте текущий Core для преобразования.
