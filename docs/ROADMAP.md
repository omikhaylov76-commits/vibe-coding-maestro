# План развития Vibe Coding Maestro

Цель — законченный продукт: человек запускает одну команду, проект разворачивается и дальше живёт без ручного ремонта. План опирается на два независимых ревью версии 0.3.0-beta.3: путь нового пользователя и устройство изнутри.

## Главный шов

Проверки Maestro сравнивают состав файлов проекта с составом той версии, которая их запускает. До 0.3.0-beta.4 проекты звали Maestro через `@latest`, а `upgrade` умел обновлять только с 0.2. Значит, любой выпуск, меняющий состав файлов, сразу покрасил бы проверки во всех проектах, и обновить их было бы нечем. Поэтому первым идёт фундамент обновлений.

## 0.3.0-beta.4 — фундамент

Статус: выпущена 31.10.2026. Состав файлов проекта не меняется, поэтому выпуск ничего не ломает.

- `upgrade` с любой опубликованной версии; прошлые версии и их файлы объявлены в пакете.
- Точная версия Maestro в каждом созданном проекте вместо `@latest`; `upgrade` переписывает её сам. Обёртка `vibe-maestro` зависит от точной версии.
- Вместо `manifest-canonical-mismatch` — понятное сообщение: «проект версии X, проверьте или обновите так».
- Экономный CI: отмена устаревших прогонов, один быстрый прогон на ветке, полная матрица на pull request и `main`, `npm run check` перед пушем.
- Понятные ошибки в `create`, `doctor` и `preflight` вместо stack trace и `ENOENT`.
- README и руководство — только через `npx`, без обещаний, которых код не выполняет.

## 0.3.0 — готовый продукт

Статус: выпущена 31.10.2026 (0.3.0, исправления — 0.3.1). Все изменения состава файлов — одним заходом, с миграцией в `upgrade` с 0.3.0-beta.1 – beta.4 и 0.2.

- Цикл «план утверждён → работа» описан и проверяется; `doctor` и `preflight` не противоречат друг другу по статусу плана.
- Личность проекта — по `project.id`, а не по имени папки; Unicode в путях приводится к NFC. Повторный `create` не переписывает отображаемое имя и даты.
- `doctor` не ругается на то, что велят сами протоколы; `wiki/index.md` принадлежит проекту; есть образцы передачи, ADR и записи хода работы.
- Правила честности — в `.claude/rules/` (файл Maestro), правила проекта — в своём файле рядом; `AGENTS.md` ссылается на те же правила.
- `.claude/settings.json` с запретами по умолчанию: не читать `.env`, не править файлы Maestro; push, publish и удаление — только с вопросом. Файл принадлежит проекту: проект свободно меняет правила, `doctor` и `upgrade` его не трогают. В Claude Code правило «спросить» нельзя перекрыть разрешением из другого файла, поэтому управлять им должен сам проект.
- Правила точечной правки — в `.claude/rules/` рядом с правилами честности: менять минимум, не строить абстракции под один случай, не править тесты ради «зелёного», сначала читать код.
- В шаблоне плана — раздел «Где правим»: какие файлы и модули трогает порция, что проходит через их границы и какой командой порция проверяется.
- `/build` начинает сессию одинаково: `wiki/hot.md` → история Git → прогон проверок до новой работы; после утверждения плана работа идёт в новой сессии.
- Ревьюер и помощник-разведчик для больших файлов только читают (`Read`, `Grep`, `Glob`). Ревьюер сверяет работу с планом, а не стиль; разведчик работает на дешёвой модели и отвечает коротко.
- Навыки: пустые рекомендации убраны; в протоколе есть шаг выбора навыков — установленные, официальные каталоги, чужое только после «да» человека, в плане записано, что взято.
- Изменение плана после утверждения замечается.
- Прерванный `create` оставляет метку и говорит, что убрать.
- Сценарий нового пользователя проверяется автотестом; перед публикацией — независимое ревью.

## 0.4 — движок для длинных проектов

Начинается после выпуска 0.3.x. Новых файлов-протоколов не добавляем: всё ниже — шаги в существующих протоколах, команды и проверки. Одно исключение — `protocols/completion.md`: завершения проекта в жизненном цикле не было вовсе, это недостающий этап, а не повтор.

Выпускается частями:

- **0.4.0** (выпущена 31.10.2026): ключи API без поиска файлов, `.gitignore` шаблона, раздел «Как подстроить защиты под проект», паспорт проекта, протокол «Завершение», правило новой сессии после закрытой порции.
- **0.4.1**: команда упаковки `vibe-maestro pack` и счётчик размера сессии `vibe-maestro context`.
- Остальное ниже — следующими выпусками 0.4.

### Завершение проекта

- **Паспорт проекта** `wiki/passport.md` — принадлежит проекту, ведётся с первого дня: репозиторий и тег сдачи, где работает, домен и DNS, данные и резервные копии, внешние сервисы и чей аккаунт, **имена** переменных окружения (значения — никогда), расписания, как запустить, обновить, откатить. Пустой раздел — явное «не применимо». Подходит и проекту без кода. *Вошло в 0.4.0.*
- **Протокол «Завершение»** `protocols/completion.md`: критерии «готово» проверены, тесты зелёные, тег сдачи, паспорт полон, документы для заказчика, итоговая передача, план закрыт, уроки записаны; отдельно — закрытие внутреннего проекта без сдачи. *Вошло в 0.4.0.*
- **Команда упаковки `vibe-maestro pack`** — детерминированный zip без зависимостей: `git archive` тега сдачи плюс документы для заказчика, включая шаг «смените все пароли и ключи». Защиты: отказ при секретах, при внутренних папках `wiki/`, `maestro/`, `.claude/`, `protocols/` в архиве, при неполном паспорте; повторная упаковка того же тега даёт тот же архив. *0.4.1.*

### Напоминание о новой сессии

- **Правило текстом** в `.claude/rules/maestro.md`, `protocols/build.md` и `protocols/handoff.md`: закрыл порцию — передача дел и предложение начать новую сессию; вторую крупную порцию в той же сессии без согласия человека не начинать. Причина — замер на живом проекте: почти все токены уходят на повторную пересылку истории в длинных сессиях. *Вошло в 0.4.0.*
- **Счётчик `vibe-maestro context`** — размер текущей сессии по журналу Claude Code; агент запускает его при закрытии порции и простыми словами говорит, пора ли в новую сессию. Пороги 40 и 70 % — гипотеза, проверяется повторным замером. *0.4.1.*

### Старт проекта

- **Знакомство в первой сессии (`/start`)** — шаг поверх `protocols/discovery.md`. Лучше подробно расспросить в начале, чем спотыкаться потом.
  - Как спрашивает: по одному вопросу, простыми словами, блоками. На любой вопрос можно ответить «не знаю» — это записывается как UNKNOWN и возвращается позже. Можно прерваться и продолжить: черновик ответов хранится в проекте. Где можно, агент предлагает значение по умолчанию, человек подтверждает. `/start` можно перезапустить, чтобы пересмотреть договорённости.
  - Блоки:
    - проект и цель: что делаем, для кого, что значит «готово», сроки, бюджет;
    - роли: кто принимает решения, кто исполняет, от чьего имени можно писать людям;
    - что требует отдельного «да»: деньги, публикация, сообщения людям, удаление, отправка в облако, чужой код, смена настроек — и что агент делает сам;
    - как общаться: язык, уровень технических слов, длина ответов, «одно решение за раз», что значат FACT / HYPOTHESIS / UNKNOWN;
    - доступы и секреты: ключи только в `.env`, не в чат и не в git, пароли и коды вводит человек;
    - хранение и восстановление;
    - что уже есть: материалы — в `maestro/inbox/`;
    - ограничения и риски: законы, правила сервисов, чувствительные данные;
    - ритм работы и передача дел.
  - Финал: сводка «как мы работаем» на одном экране, «да» человека, запись в `.claude/rules/project.md`, `wiki/roadmap.md` и `wiki/restore.md`. Настройки защит в `.claude/settings.json` — только с отдельного «да». Правила честности из `.claude/rules/maestro.md` знакомство не отменяет и не ослабляет. Первый шаг после знакомства один — `/plan`, и он назван одинаково в README, на финальном экране мастера и в `wiki/hot.md`.
- **Копия в облаке с первого дня.**
  - Мастер `create` предлагает создать закрытый репозиторий на GitHub — только если есть `gh` и выполнен вход; по умолчанию «нет», для `--yes` — флаг. В мастере по-прежнему не больше трёх решений.
  - `doctor` предупреждает, если у проекта нет remote или есть коммиты, не отправленные в upstream. Проверка идёт по локальным данным git, без сети. Это предупреждение, `preflight` оно не блокирует.
- **Страница «Как восстановить на новом компьютере»** — заготовка `wiki/restore.md`, принадлежит проекту: что лежит в облаке, чего там нет (секреты, `.env`), что поставить, как проверить. `README.md` проекта создаётся только если его нет; существующий не трогается никогда. `upgrade` добавляет только отсутствующее.
- **`.gitignore` шаблона:** `.claude/worktrees/` (временные рабочие копии) и `.claude/settings.local.json` — не полагаться на глобальные правила git конкретного компьютера. `upgrade` дописывает только недостающие строки, строки проекта не трогает. *Вошло в 0.4.0.*

### Защиты

- **Раздел «Как подстроить защиты под проект».** *Раздел руководства вошёл в 0.4.0; предложение в `/start` — позже.*
  - Четыре уровня: шаблон Maestro → `.claude/settings.json` и `.claude/rules/project.md` проекта (принадлежат проекту) → личный `.claude/settings.local.json` → режим разрешений сессии Claude Code.
  - Порядок правил: deny → ask → allow. `ask` из проектного файла не перекрыть `allow` из личного — только правкой самого `settings.json`.
  - Три-четыре типовые настройки простыми словами. Например:
    - «отправка в облако без вопроса — если репозиторий закрытый и работаете один; `--force` по-прежнему с вопросом»;
    - «свои команды проекта».
  - Разрешения меняются только по «да» человека.
  - «Отправка в облако без вопроса» предлагается в `/start` и только с «да». После этого `ask` остаётся лишь на `git push --force` / `-f`. Для неинтерактивного создания — отдельный флаг. По умолчанию поведение прежнее.
- **Ключи API без поиска файлов.** Запрет `Read(.env)` убран из шаблона `settings.json`; защита от попадания `.env` в git остаётся (`.gitignore`, `doctor`). Человек пишет ключ в чат — агент сам записывает его в `.env` и не повторяет; или «открой окно для ключа» — агент открывает `.env` в редакторе, человек вставляет ключ сам. Честно: написанное в чат остаётся в истории. *Вошло в 0.4.0.*

### Работа и память

- **Команда `vibe-maestro handoff`.**
- **Память не разрастается** — вместе с командой `handoff` и контролем размера:
  - итог порции пишется в её передачу, а в плане остаётся одна строка со ссылкой;
  - при превышении порога старые записи журнала переносятся в `wiki/log/ГГГГ-ММ.md`, история не переписывается;
  - `doctor` предупреждает о длине `wiki/hot.md`, активного плана, журнала и передач;
  - закрытые правки плана и старые аудиты уходят в архив и не читаются целиком.
- **Напоминание о передаче в длинной сессии:** проверка замечает, что `wiki/hot.md` отстал от коммитов.
- **Учёт закрытых порций** списком в плане, который читает `preflight`: закрытую порцию нельзя открыть заново по ошибке.
- **Рецепт крупной порции** — текст в `protocols/build.md`, без привязки к одному агенту: правка в отдельной рабочей копии (`git worktree`); до правок снимаются эталоны вывода ключевых команд «как было», после — побайтовая сверка; независимое ревью только для чтения; слияние — после этого.
- **Карта кода `wiki/map.md`** — папка, назначение, команда проверки, — которую собирает команда без ИИ.

### Прочее

- **Проект под заказ** вместе с брифом одной командой.
- **Раздел о коннекторах** (MCP).
- **Меньше мелких протоколов.**
- **Проверка «замка» утверждения.** Гипотеза: команда, которую человек вводит сам в своём терминале.

## Не делаем

- Автоустановку навыков и коннекторов.
- ИИ внутри проверок: `doctor` и `preflight` остаются детерминированными.
- Два активных плана одновременно.
- Проверки на каждую правку файла.
- Английскую версию шаблонов сейчас.
- Новые файлы-протоколы: новое — шагами в существующих. Исключение — `protocols/completion.md` (недостающий этап жизненного цикла).
- Набор «профилей» защит с множеством переключателей.
- Блокирующие проверки копии в облаке: только предупреждение.
